# Relationship API Demo

This example uses native Fiber v3 and the generic go-crud router adapter. It runs JSON APIs and an autogenerated OpenAPI explorer over a seeded in-memory SQLite database.

## Features

- `PublishingHouse` with has-one `Headquarters`, has-many `Authors` and `Books`
- `Author` with has-one `AuthorProfile` and has-many `Books`
- `Book` with belongs-to `Author`/`PublishingHouse` and has-many `Chapters`
- OpenAPI explorer at `/meta/docs/` and documents at `/openapi.json` and `/openapi.yaml`
- Queries such as `GET /api/authors?include=profile,books,publisher`

Published go-crud v0.27.3 supports many-to-many and nested includes such as `authors?include=tags`, `authors?include=books.tags`, `authors?include=books.chapters`, `books?include=author.profile` and `authors?include=publisher.headquarters`. Regression tests check returned relationship contents, including the requested nested headquarters.

## Running

```sh
cd examples/relationships
GOWORK=off go mod verify
GOWORK=off go run -mod=readonly .
```

The checked-in graph has no replacements and uses published go-crud v0.27.3, go-repository-bun v0.16.2 and go-router v0.65.3 with Fiber v3.6.1. Keep checksum verification enabled. Root development changes are not used by this module. Fiber v2 remains an indirect provider compatibility dependency.

The default address is `:9091`; set `RELATIONSHIPS_ADDR=127.0.0.1:9091` to bind locally, or `127.0.0.1:0` to choose an ephemeral port. Readiness is logged after managed Serving. SIGINT/SIGTERM stop admission and allow ordinary requests five seconds to drain; startup and shutdown errors exit nonzero. There are no owned RPC, WebSocket or SSE workers. The database is ephemeral and closes when the host returns.

```sh
GOWORK=off go test -mod=readonly -race ./...
```

Tests cover schema, many-to-many and nested relationship contents, CRUD, OpenAPI responses, startup failure, pre-cancellation, cancellation during binding, ordinary request drain, deadline expiry and shutdown error propagation. Controlled held handlers are test-only; browser rendering acceptance remains a separate check.
